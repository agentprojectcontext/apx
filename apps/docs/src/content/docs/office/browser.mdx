Agents browse the web in a real browser built into the [desktop app](/devices/desktop/). You watch every page live in
the chat's **Browser** side panel, and you can take the wheel at any moment.

## Watching an agent browse

When an agent opens a page, the chat shows a browser card and the **Browser** side panel follows the tab live: "Vera
is browsing · supplier.example.com". From the panel you can open the tab in a separate window or in your own browser.

> **You:** Vera, compare the shipping prices on our two carriers' sites for a 2 kg box to Córdoba.
>
> **Vera:** Opening both rate calculators… The first is 4.20 cheaper, but the second delivers a day earlier.

## Taking control

Press **Take control** on a tab and it is yours: click, type, scroll. The agent waits. **Give back** returns it.

The agent can also ask you to take over. When a site wants a login, a password, a 2FA code or a captcha, the agent
hands the tab to you ("Vera needs you to take over") and waits up to 5 minutes while you finish. Then it carries on
from the page you left it on.

<Aside type="caution" title="It never types your passwords">
The embedded browser refuses to type into password, one-time code and card fields, whatever the autonomy. Those are
always a hand-off to you. Agents are also told never to ask for passwords in chat.
</Aside>

## Approved JavaScript execution

On unreleased staging builds, an agent can use `browser_evaluate` in its existing APX tab. Supply either a JavaScript
expression in `script`, or a local `.js` `path` plus the SHA-256 of its exact bytes in `sha256`. File access follows the
agent's normal folder permissions; URLs are not script sources. VM chats accept inline code only, never host files.
Use an async IIFE for statements and return a value:
`(async () => ({ title: document.title }))()`.

Every execution needs your confirmation, even in Total. Review the entire script (and the exact file matching the hash)
before approving: arbitrary JavaScript can read private page data or send requests as your signed-in account. The normal
typing tool's credential-field protection is **not a JavaScript sandbox**. Never approve code handling passwords, 2FA or
card data. The tab's profile and take-control/handoff rules still apply. This method is not exposed to outside MCP clients.

APX awaits promises and returns untrusted JSON text (up to 16,000 characters); undefined becomes null, bigint becomes text,
and circular or oversized results fail. Scripts are limited to 64,000 characters (files: bytes). Chromium has a 5-second
execution limit and APX stops waiting after 7 seconds. A timeout is **not cancellation or rollback**: timers, requests or
other side effects may continue. Verify the page before retrying, especially after a send. This adds an agent tool, not a
new DevTools panel or remote debugging port. Desktop must load the matching new build; a core-only restart is not enough.

## Profiles

Each agent browses with one of three profiles, set per agent in **Settings › Agents** (or the agent's own panel):

| Profile | Cookies and logins |
|---|---|
| **Shared** | One profile shared by every agent that uses it. Log in once, all of them benefit. The default. |
| **Isolated** | A profile of that agent's own; nothing leaks between agents. |
| **Incognito** | Nothing is kept. Logins cannot be imported into it. |

## Importing your logins

If you are already signed in to a site in your own browser, there is no need to log in again in APX's.
**Settings › Browser** copies your sessions into the browser's shared profile: pick a source browser (Chrome, Brave,
Arc, Edge, Zen or Firefox), filter the domains and import only the ones you need. Your browser may ask for
permission; the values never leave your machine.

Agents can ask for this too. When a site wants a login, an agent can ask to use your session for that one domain. That
asks your OK every time (only total autonomy skips it), and agents try it before a hand-off.

## Without the desktop app

When no desktop app lends a browser (a server, or a Mac with the app closed), the core starts its own **headless**
Chrome, Chromium or Edge, without a window, on its first browser call. It browses the same way, but nobody can take
over there and your own logins are not used. `APX_HEADLESS=off` turns it off; `APX_CHROME` points it to a specific
browser.

## From the terminal

`apx browser` drives the same browser from your shell, handy for scripts and for checking what an agent sees.

<Terminal command="apx --help">{`apx browser tabs
apx browser open <url> [--profile shared|incognito|agent:<id>] [--by <agent>]
apx browser nav <tab> <url>
apx browser snapshot <tab>
apx browser click <tab> <ref>
apx browser type <tab> <ref> <text> [--submit]
apx browser shot <tab> <file.jpg>
apx browser close <tab>
apx browser control <tab> user|idle|done
apx browser cookies                          List browsers whose sessions can be imported
apx browser cookies <source> [filter]        Domains with cookies (counts only)
apx browser import <source> <domain,…> [--profile shared|agent:<id>]`}</Terminal>

`snapshot` lists the page's elements with refs that `click` and `type` take. `control` sets who holds the tab.
`cookies` shows only counts, never values.

Outside apps such as Claude Code can use this browser too, through `apx mcp`. See
[Outside clients](/extend/outside-clients/).

## Computer use on macOS

Beyond the browser, agents can use your Mac's apps: look at the window in front, click, type and press keys. It is
**off by default**.

<Shot name="settings-desktop" alt="Settings, Desktop: quick chat shortcut, start with the computer, and the Computer use switch with Screen Recording and Accessibility permissions" caption="Settings › Desktop" />

<Steps>

1. Open **Settings › Desktop** and turn on **Let agents use this computer**.
2. Grant macOS **Screen Recording** (to see the window an agent works on) and **Accessibility** (to read a window's
   buttons and fields, click and type). **Open System Settings** takes you there.
3. Ask in a chat: "Tomás, open the label printer app and print today's 12 shipping labels."

</Steps>

While an agent uses the computer, the chat shows **What the agent sees**, a live view of the screen.

- Looking at the screen asks your OK, and so does every click, key and typed text. Under total autonomy none of them
  ask.
- Every 60 actions in one turn it stops and asks whether to go on, in every autonomy.
- It refuses password fields, and refuses a click where another app's window covers the point.
- A real click waits until your mouse is at rest, so it does not fight you for the pointer.

<Aside type="danger" title="Emergency stop">
**Stop** in the live view, or **⌘⇧Esc** from any app, ends every turn that is using the computer, right away. Ask
again whenever you want.
</Aside>

<Aside type="note">
Computer use is macOS only for now. Windows and Linux do not lend the capability yet.
</Aside>
