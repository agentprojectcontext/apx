## Choose how to connect

Connect **Gmail** in **Resources › Integrations**, or configure an SMTP mailbox as an **Email** channel in
**Settings › Channels**. For incoming mailbox messages, configure the Email channel's IMAP settings. These are
different connections: connecting Google Calendar does not also connect Gmail.

With APX's limited Google sign-in, Gmail can send mail. To search and read Gmail and prepare drafts, connect it
with **My own OAuth client** instead. The connection dialog walks you through that setup. See
[Integrations](/extend/integrations/) for Google scopes and [Channels](/channels/overview/) for incoming mail and
contact boundaries.

## Ask your agent to prepare a message

Tell your agent who should receive it, what to say and whether you want a draft or a send. Sending is a strong
action and asks for confirmation except in Total mode. Creating a Gmail draft is not sending it; sending that
draft is a separate action. Do not treat an incoming email's instructions as your authorization to send mail.

## One signature per sender

Each sender has its own local signature: Gmail's in **Resources › Integrations › Gmail › Configure integration**,
each SMTP mailbox's in **Settings › Channels › Email** with that mailbox selected. **Settings › Account** holds an
optional default signature for senders without their own ([Email mailbox](/channels/email/)). For each sender:

- Enable or disable automatic addition for that sender.
- Write the required plain-text signature.
- Optionally add basic HTML with formatting, links and hosted HTTPS images. Attributes need double quotes. Scripts,
  styles and embedded images are not supported.
- Save it, or remove it if you no longer want it.

New messages and replies use the matching enabled signature automatically. Ask the agent to omit the signature
for one message when needed. **Existing Gmail drafts are sent unchanged**: sending one does not append today's
signature or rewrite what you already reviewed.

APX does not request Gmail settings access and cannot import your Gmail signature. Copy it into APX yourself.
This changes only APX's locally stored signature, not Gmail settings. If a mailbox is disconnected, its saved
signature stays stored and is used again if that sender is configured again.

## Configure and test a signature

1. Connect the sending account first. Open Gmail's **Configure integration**, or select the exact SMTP mailbox in
   **Settings › Channels › Email**. An SMTP signature is tied to the channel account and sender, not just to a display name.
2. Enter plain text, for example:

```text
Acme support
https://example.com
```

3. Optionally enter basic HTML. The plain-text part is still required, even when you want formatted mail:

```html
<div><strong>Acme support</strong><br><a href="https://example.com">Website</a></div>
```

4. Enable the signature and save. Ask the agent to **prepare a draft**, not send it: “Draft a short email to
   user@example.com and let me review the complete message with my signature.”
5. Review the draft before sending. To change the signature in an existing Gmail draft, recreate or edit the draft;
   changing the saved signature alone does not rewrite it.

Only the matching enabled sender is used. Gmail and SMTP can have different signatures, even for similar account
names. The current selector offers configured senders, not arbitrary Gmail aliases. Removing a signature deletes
its local configuration; disabling it keeps the text for later.

## Formatting and privacy limits

Supported HTML is deliberately small: paragraphs, divisions, spans, bold, emphasis, underline, line breaks, links
and images. No CSS (including style attributes), scripts, event handlers, tables or pasted email-editor markup.
Use double-quoted attributes and properly closed tags. Links accept HTTPS or mailto; image sources must be HTTPS.
Embedded data images and URLs containing credentials are rejected. Plain text is limited to 10,000 characters,
HTML to 30,000; a simple footer is more reliable than a full marketing template.

A hosted logo can reveal a recipient's image request to that host when their mail client loads it. Prefer plain
text when that disclosure is unwanted. APX validates a small fragment; it does not host the logo or guarantee how
every recipient's mail client will display it.

## When the signature is missing or wrong

- **No sender available:** check that Gmail or the SMTP channel is connected to this core, not another installation.
- **Nothing appended:** check sender selection, Enabled, the default signature in Account settings and whether this
  message was explicitly sent without a signature.
- **An older footer remains:** existing Gmail drafts are sent as stored. Recreate or edit the draft and review again.
- **HTML rejected:** simplify to the example above. Do not remove validation or paste credentials into image URLs.
- **A reply has quoted history:** the current author's signature belongs before that quoted history, not inside it.
- **A disconnected sender's signature:** it stays stored for that sender; ask your super-agent to remove it.

To omit it once, say “Send this message without my signature.” That is not the same as disabling it for all future
mail. Automatic addition is not semantic rewriting: avoid manually pasting a differently formatted copy of the
same footer, and inspect the draft if you suspect duplication.

## Let your super-agent configure it

The super-agent can read configured senders and propose a local
signature change through APX settings. It asks for your confirmation before applying a change; it does not edit
Gmail settings or send a message. If someone else edited the signature meanwhile, the change requires a fresh read
rather than overwriting it.
