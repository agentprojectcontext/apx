Ask an agent for a chart, a dashboard, a checklist or a small tool, and it builds a **widget**: a self-contained
piece of HTML that shows right in the chat. Widgets are live: when the agent changes one, every place it is open
updates at once. Pin the useful ones to a project's **Board** and you have a dashboard your agents keep up to date.

## Agents build them in chat

Ask in plain words:

> **You:** Vera, make me a widget with this week's orders by day and the top 5 products.
>
> **Vera:** Here it is. It reads the numbers from the store's export; ask me to change anything.

The widget appears inline in the answer. To change it, just ask ("make the bars green, add last week for
comparison"): the agent edits the same widget instead of making a new one, and you see the new version in place.

Widgets are themed to match the panel (light and dark) and reach no network unless they declare where they get live
data from: then the widget's header says **Live data from** and the hosts. A widget that connects out asks your OK
while outside content is in the turn.

A widget can also show the project's own images, video and audio without copying them in: ask for "a preview of
the reel with `reels/take-1.mp4` playing behind it" and the widget plays that file from the project's folder. It
reads only files the widget names, inside its own project, and only media (no documents or code).

## The Widget side panel

Open the side panel on **Widget** to see every widget the agent built in this chat, larger. A widget's header keeps
the same few actions wherever it shows, and the rest under **More**:

| Action | What it does |
|---|---|
| **Edit** (pencil) | Edit mode: point at a part and change it. |
| **Ask its agent for changes** | Opens the widget's chat with the agent that keeps it. Shown where there is no chat (Board, Apps, Files). |
| **Share** | Private by default; **Anyone with the link** can view it without editing. **Copy link** to send it. |
| **More › Pin to the board** / **Unpin from the board** | Puts it on (or takes it off) the project's Board. |
| **More › Pin to Apps** | Lists it under Apps in the sidebar, to open full screen. It stays a widget: violet, and laid out as one. |
| **More › Open in another window** | The widget alone, in a window of its own. |
| **More › Memory** | What it keeps (settings, saved data, records), or **No memory** when it keeps nothing; export or clear it. |
| **More › Delete** | Deletes it for good. Offered on the Board and in lists, not in a chat. |

## Pin to the project Board

A project's **Overview** tab opens with its **Board**: the widgets pinned to that project, live.

<Shot name="project" alt="Acme Store's Overview tab with the Board showing pinned widgets: weekly orders, low stock and launch checklist" caption="Acme Store's Board" />

<Steps>

1. In a chat, pin a widget with **Pin to the board**, or on the Board press **Add a widget**.
2. **Ask for a new widget…** and pick an agent (or Home): it appears on the Board as soon as the agent makes it.
3. Or pick one that exists: **From this project**, or **Copy from another project**. An empty Board offers the same
   as **Create** and **Load**.
4. Drag a widget's bar to reorder; set its height and width with the handles (or the arrow keys). **Board at full
   width** uses the whole window.

</Steps>

## Share deliberately

A share link lets anyone who has it view the artifact, so check its visible data before enabling **Anyone with the
link**. Use the menu to stop sharing when no longer needed. The link needs a reachable APX host; creating it does not
publish your loopback-only core to the internet. Do not expose the whole panel just to make a widget link reachable.

Agents cannot replace a published artifact's HTML: unpublish it yourself before requesting changes, or ask for a
separate artifact. A public page shows only its own HTML: it cannot reach APX's state, your private files or any
action, and it has no owner chat to approve one. Turning on a public address (Settings › Devices) makes every page
already shared reachable too, so review them first. Export without memory when distributing a
template rather than sharing your records. See [artifact memory and export](/office/artifacts/).

## Apps: what you keep at hand

**Apps** in the sidebar lists the apps agents made (green) and any widget you pinned there (violet). Being in Apps is
where you keep it, not what it is: a widget pinned there stays a widget, and an app you take out of Apps stays an app.
Each opens full screen, from any project, with who made it and where it lives. **Unpin from Apps** takes it off the
list; the artifact itself stays.

Web pages are documents, not board tiles: they are not pinned to a board. You find them in their chat and in the
project's **Artifacts** list, and open them on their own screen.

## Where widgets belong

A widget belongs to one project, or is global when it was made in a chat outside any project. A project's chats see
only that project's widgets; chats outside a project see only the global ones. To use a widget somewhere else:

- **Copy** it into another project (from that project's Board: **Add a widget** › **Copy from another project**).
- **Open it as an app**, from any project.
- **Share** its link.

An agent never reaches into another project's widgets.

<Aside type="note">
Widgets are kept in APX's database, not as files in your project, so a backup of APX keeps them all and a share link
always shows the current version.
</Aside>
