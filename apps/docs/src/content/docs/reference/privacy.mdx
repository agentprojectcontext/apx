For cookies and optional analytics on apxagent.app, see [Website privacy](/reference/website-privacy/). The choices below apply only to the application.

APX runs on your computer and keeps your chats, agents, files and keys there. To know how many people install it, get
through the setup and keep using it, it tells the APX project a little about your install. This page lists all of it.

## Every install: the steps it goes through

Under a random id made for this alone (it is not your home id, your name or anything about your computer), APX sends
each of these once, when it happens:

| Step | When |
|---|---|
| Installed | The core starts for the first time. |
| Opened | The panel opens for the first time. |
| Answer on statistics | You answer the question below (again if you change it). |
| Setup finished | You finish the first-run setup. |
| First use | You send your first message. |
| Updated | APX starts on a new version. |

Each one carries the APX version, the operating system (`darwin`, `linux`, `win32`), the processor (`arm64`, `x64`)
and how APX was installed (desktop app, install script or source checkout). The time is stamped by the receiving
server, not by your computer.

## Only if you say yes: usage numbers

The setup asks, with the box unticked: **Share anonymous usage statistics**. An install from before this question asks
once in the corner of the window. If you say yes, APX sends one report a day, starting the day after:

- tokens in and tokens out, summed over every model and provider;
- how many turns your agents ran;
- how many projects, agents, channels and routines you have;
- how many times, that day, you searched the Marketplace and how many of those searches found nothing (never the words
  you typed);
- how many extensions you installed, by where they came from: APX's catalog, a catalog you added, a file, a link, a
  folder or a server address. For an extension from APX's catalog, or from one of the public catalogs APX suggests, the
  report also names it and its version (`gmail@1.2.0`), since anyone can see those listings. From anywhere else it is
  only a count: never its name, the link, the file, the folder or the catalog's address;
- how many times you signed in to your [APX account](/start/account/);
- how many [public copies](/office/artifacts/#publish-a-public-copy) of artifacts you made and how many **Live from
  this computer** links you created. Each counts when it is made, even if you later stop sharing it.

These counts start when you say yes: nothing done before is counted, and saying no drops what was counted and not sent
yet. A day when none of them happened sends none of them.

Only these numbers and names. You can change your answer any time in **Settings › Advanced › Usage statistics**, which also shows
the next report's numbers and the last thing sent, exactly as it left. In Android **Settings › Privacy**, **Anonymous usage statistics** changes that same preference for the paired APX; it does not create a separate consent. Turning it off drops unsent usage counts, including a report waiting behind another send. A request already sent cannot be recalled. This switch does not stop the install steps above; use the environment settings under **Turning it off** to stop those too.

## Phone location is a separate choice

In **Settings › Advanced › Phone location** on the computer, or **Settings › Privacy** in the Android app, choose independently:

- **Location on request**: whether agents can ask for the phone's current location, without starting a trip.
- **Location during trips**: whether a phone can share positions for [errands on the way](/office/errands-on-the-way/). Turning this off also turns off errands; turning it back on does not start a trip.

If the app cannot check a setting, it shows a retry action instead of presenting it as switched off. Retrying only reads the current choice. In **Settings › In the car**, **Manage trip location** opens these choices directly.

These two choices apply to every phone connected to this APX. Android's location permission is also required on each phone. Existing permissions are not expanded by updating. Turning location off does not disconnect the phone or turn off its camera, and does not change your statistics choice.

**Settings › In the car** in APX on your computer has a separate, initially off **Errands on all phones** switch, and a **Phones** list where you can turn one phone off. Android also has **Use this phone for errands**, initially off: enable it explicitly on each phone that should participate. Turning the global switch on does not turn this phone switch on.

With both the computer and APK on **2.18.1 or later**, a trip validates its permissions before accessing GPS, then checks every five seconds. If a check cannot complete within twelve seconds, the phone stops the trip, removes its location listeners and requires you to enable that phone again. The usual detection window is up to seventeen seconds, subject to Android scheduling; this is not a real-time guarantee when Android suspends the app. A disconnected phone cannot receive a remote change immediately. The computer stops accepting trip positions as soon as you disable them, and cannot reopen that revoked trip from a stale phone announcement. A location request already running is discarded if its consent changes before it finishes. Requested location only runs while the app is active; leaving it cancels the capture. It waits up to eight seconds for a new high-accuracy fix and does not return a cached position from before the request. Agent requests do not open Android's location-settings dialogs or turn on Google Location Accuracy. If Android cannot supply a position with your current settings, the request fails; review those settings yourself if you want to allow it.

Update **both** apps for remote GPS shutdown. A **2.18.0 APK** may continue using its own GPS after the updated computer stops accepting its locations; stop it on that phone or update it. After the first remote stop, the updated computer also refuses new and reannounced trips from that old APK, even if you turn errands back on. Updating the APK and turning **Use this phone for errands** back on is required to resume; an older trip cannot acquire the new consent. Pending place searches are cancelled at the same boundary. A **2.18.1 APK with a 2.18.0 computer** cannot validate the new location choices and does not start sharing trip or requested locations. Update the computer to use them. Reconnecting never clears the phone's safety pause.

## Never sent

Your messages or anything an agent wrote; what you type in a search; names of people, agents, projects or files; folder
paths, links and addresses; which extensions you have from a file, a link, a folder or a catalog APX does not suggest;
the content or address of a public copy or a live link; which models or providers you use; API keys, tokens or secrets; your home id; your IP address on purpose (the receiving service sees
it to answer the request, as any web request does, and APX does not store it).

## The Chrome extension

The APX extension for Chrome shows this APX in Chrome's side panel, and lets APX's agents work in the tabs of its
**APX** tab group. The extension itself collects nothing: it makes no network requests of its own, stores nothing and
has no analytics. The panel is APX's own screen, served from `127.0.0.1` on your computer, so what you type there is
handled by APX as in the app: kept on your computer, and sent only to the model providers you set up in APX to answer
it.

It reads and acts on a web page only in a tab of the **APX** group, only when an agent works there for something you
wrote in the side panel. What it reads goes to APX on your computer through Chrome's native messaging (never over the
network), and from there, like any page an agent reads, to the model provider answering. Tabs outside that group are
never read. The extension adds nothing to the reports above.

## Only when you use them: account, public copies, catalogs

These send something only when you use them, and are not part of the reports above:

- **Your [APX account](/start/account/)** (optional). Signing in with Google keeps that Google account in Firebase
  Authentication, and a private profile with your APX ID, your Google name and photo address and the username you
  choose, in the same `apx-agents` project. Your projects, chats, agents and files are not uploaded.
- **A [public copy](/office/artifacts/#publish-a-public-copy)** of an artifact. Only when you choose **Public** and
  confirm the review, the page (and the saved data you chose to include) is uploaded to `artifact.apxagent.app`,
  where anyone with its link can see it and search engines may list it. **Only you** stops sharing it.
- **The Marketplace.** To list extensions and tell an official one from others, APX downloads APX's catalog from
  `marketplace.apxagent.app`, and the catalogs you added from where they live (GitHub, a git address, an https
  address). These are plain downloads: nothing about you or your install is sent with them.

## Where it goes

The install steps and usage numbers go to a Google Cloud Firestore database of the APX project (`apx-agents`, in the United States), written without an
account. Its rules accept only the shapes above, stamp every time on the server and let no one outside the project
read anything back.

## Turning it off

<Aside>
Any of these stops everything, including the install steps: `APX_TELEMETRY=off` in the core's environment or
`core.env`, `DO_NOT_TRACK=1` ([Console Do Not Track](https://consoledonottrack.com)), or a `CI` variable.
</Aside>

To start over with a new random id, delete `telemetry-id` in your APX home (`~/.apx/v2`). To have an install's records
removed, open an issue on [GitHub](https://github.com/agentprojectcontext/apx/issues) with the telemetry id shown in
Settings › Advanced.
