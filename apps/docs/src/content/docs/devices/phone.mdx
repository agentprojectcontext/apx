Your phone talks to the same core as the panel, through the same protocol. It never gets the core's own token:
it trades a one-time code for a key of its own, which you can take back at any moment without touching anything
else.

<Aside type="caution" title="First, the phone has to reach the core">
A core that only listens on its own computer (the default) can't be reached by a phone. Open it to your local
network or your Tailscale network first: in **Settings › Connections › Devices** under **Who can reach this APX**,
in the desktop app's first run, or with `apx expose` on a server ([Run APX on a server](/devices/server/)).
</Aside>

## Open on your phone

The quickest way: click **Open on your phone** in the top bar (it's also in your account menu). A QR appears.

<Shot name="phone-pair" alt="The Open on your phone dialog with a pairing QR code and the code typed out below it" caption="Open on your phone" />

Scan it with the phone's camera. It opens the APX app, pairs the phone if it isn't paired yet, and opens the chat you
were looking at. A phone already paired with this core just opens the chat.

The code under the QR works once, for 10 minutes. While the dialog is open APX renews it before it runs out, and
closing the dialog voids it. If the core only listens on this computer, the dialog says **Your phone cannot reach
this core yet** instead of showing a QR.

### From the phone's browser

You don't need the app to use the panel on a phone. Open the core's address in the phone's browser (the Tailscale
address, or the LAN one such as `http://192.168.1.20:7440`). The panel asks to **Pair this device**: type a code from
**Settings › Connections › Devices › Pair a device** or from `apx pair`, and the browser keeps its own key. The panel
adapts to the narrow screen.

<Shot name="phone-home" alt="The APX panel at phone width, with the Home chat open" frame="phone" />

## Pairing codes and device keys

Every pairing works the same way, whether it's a phone, a browser or another computer:

- The code has **8 characters**, without look-alikes (no `0`/`O`, no `1`/`I`), and lives **10 minutes** in the core's
  memory. Restarting the core voids pending codes.
- It works **once**. The device trades it for a key of its own; the core stores only that key's hash.
- **Five wrong codes** void every pending code and pause pairing for **five minutes**.
- The QR carries an `apx://pair?…` link with the code and the addresses the core can be reached on. If you set
  `APX_PUBLIC_URL` (a VPS or Tailscale address), it goes first.

You can make a code in three places:

- **Open on your phone** in the panel (also opens the current chat on the phone).
- **Settings › Connections › Devices › Pair a device**: a QR, the code and the addresses.
- The terminal, on the machine that runs the core:

<Terminal command="apx pair">{`Pairing code: ABCD2345
Expires at 10:40:00 (in about 10 min)

Addresses a device may reach this core on:
  https://<machine>.<tailnet>.ts.net

In the APX app, open Pair and paste the link, or enter an address and the code:
  apx://pair?c=ABCD2345&u=https%3A%2F%2F<machine>.<tailnet>.ts.net`}</Terminal>

## See and revoke devices

<Shot name="settings-devices" alt="Settings, Devices section: paired devices with their platform and last seen time, and the connection options" caption="Settings › Connections › Devices" />

**Settings › Connections › Devices** lists every paired device with its platform and when it was last seen. The trash
button (**Remove**) revokes that device: its key stops working at once, and only that one. A revoked phone goes back
to the pairing screen.

From the terminal:

```bash
apx devices                 # list paired devices
apx devices pair            # a new code (same as apx pair)
apx devices revoke <id>     # revoke one device
```

## The APX app for phones

### Install it on Android

The Android app comes with every v2 release. It isn't in Google Play yet, so you install the file yourself:

<Steps>

1. On the phone, open the [v2 releases](https://github.com/agentprojectcontext/apx/releases?q=v2&expanded=true) and, in the newest one, download `APX-<version>-android.apk`.

2. Open the downloaded file. The first time, Android asks you to allow installing apps from your browser (or from
   Files): allow it, go back and tap **Install**. If Play Protect warns that it doesn't know the app, tap **Install
   anyway**.

3. Open APX and pair it, as in [Open on your phone](#open-on-your-phone).

</Steps>

It installs beside APX v1's phone app; the two don't touch each other.

<Shot name="phone-app" alt="The APX app on a phone, with the Home chat open" frame="phone" />

**Updating.** The app doesn't update itself yet. When a new version is out, download its APK the same way and install
it over the one you have: your pairing and settings stay. If Android says the app conflicts with one already
installed, that one is a build you made yourself or a test build: uninstall it, install the release's APK and pair
again. From then on each release installs over the last one.

<Aside type="note" title="iPhone">
The iOS app isn't in the App Store yet. To try it you build it from the repository (`apps/mobile`), as below.
</Aside>

What it does once paired:

- **Pairs** by scanning the QR, opening an `apx://pair` link, or typing the address and the code by hand. It keeps its
  key in the system's secure storage.
- **Shows your Home chat live**, over the same socket the panel uses.
- **Shows your pinned widgets and apps** (the Apps button), each full screen, sandboxed the same way the panel does it.
- **Lends the phone to the core as a node**: agents get `phone_location` and `phone_photo`, but only while the phone
  is connected. A photo is always taken by you on the phone (the app shows why the agent wants it). Location asks the
  system's permission once, and asks for your OK whenever outside content is in the turn.
- **Takes notifications**, described next.

If you can't reach the core, the app keeps its pairing for when it can. Unpairing (or revoking it in the panel) sends
it back to the pairing screen.

To run it from a checkout:

```bash
cd apps/mobile
npm install
npx expo start      # Expo Go or a dev build; the core must be reachable on the network
```

The default release build configuration targets **ARM64 (`arm64-v8a`)**. Other architectures can be built, but do
not assume an APK supports an older ARM32 phone or an x86 emulator: check the specific release artifact before
installing. Build configuration alone is not proof of the ABIs inside an already published APK.

Pairing lends the connected phone's **location and camera**, not general Android app control, ADB or access to every
file on the phone. Location uses a foreground system permission; do not treat it as continuous background tracking.
A camera action still requires you to frame and take the photo. If the app is disconnected or suspended, do not
assume these node capabilities remain available just because the pairing key is saved.

## Navigate the Android app

The native app is more than Home chat. The bottom navigation offers **Chats**, **Inbox**, **Tasks**, **Sessions**
and **More**. Under More, open routines, agents, projects, channels, memory, apps, files and settings. Some sections
show summaries and open detail screens rather than every desktop configuration control; the same core owns their data.

Use **Tasks** to inspect work and its attachments, and routines to inspect or edit scheduled work. Read the actual
state before treating a queued, waiting or interrupted run as complete. Starting or editing work uses the same
permissions and confirmations as other APX clients, not a separate unrestricted mobile account.

## Attachments, images and voice

In chat, use the attachment controls to select a photo or file, or record a voice message. A camera request from an
agent shows why it needs the image and lets **you** take or decline it; pairing does not authorize silent camera use.

Open a received/generated image or video to inspect it. Its media actions offer **Save to gallery** for supported
pictures and videos (with Android's media permission), and **Share or open** to pass the file to another app or keep
it through the system sheet. Other documents use sharing/opening rather than the photo gallery. Long-press a text
message for copy, selection or sharing. These actions affect the file on your phone, not the core's original.

If saving fails, check the app's media permission and that the file has finished downloading. An error or an open
share sheet is not proof that Android saved it. Confirm in your gallery or destination app. If the file is private,
choose the recipient deliberately: sharing out of APX leaves its chat boundaries.

## Push notifications

The phone can be where your notices go, so routine news, reminders and questions from agents reach you even with the
app closed.

<Steps>

1. Give the device a way to receive push. The APX app registers itself with Expo push when the build has an EAS
   project id. Otherwise, under the device in **Settings › Connections › Devices**, use **Set up notifications** and
   paste an ntfy or UnifiedPush address.

2. Pick the phone in **Settings › Interruptions › Where notices go**. It shows up as the device's name followed by
   "(push)".

</Steps>

The same interruption budget decides what reaches the phone: daily cap, quiet hours and the rest
([Secretary](/office/secretary/)). A device can only set its own push address, and the push token never goes back to
any client.
