An extension is a folder with an `apx-extension.json` that brings several things together: skills, MCP servers,
routine templates, the secrets they need and, optionally, a sandboxed plugin. APX reads the manifest without running
anything, installs it **off**, and turning it on approves exactly the files it had.

## Find them in the Marketplace

**Marketplace**, in the sidebar, is where extensions are found, installed and connected. Resources keeps the technical
parts (Skills, MCP, Variables).

- **Extensions**, **Agents** and **Skills** are its sections. Agents lists extensions that bring ready-made agents;
  Skills, the ones that bring skills.
- **Your extensions**, under the sections, lists what you installed or connected; a warning marks one that waits on
  you (off, missing keys, an expired sign-in, a new version).
- Extensions are grouped: **Included with APX** first (Google, Asana, the channels and the browser: APX has code of
  its own for them, so they are connected, never installed or uninstalled), then APX's catalog by category, each with
  its count and **See all**.
- A card opens its page: its icon, line and publisher, screenshots, things to ask it, what it brings, about it, what
  it does, needs and does not, cost, privacy and links; beside it, the steps (install, turn on, connect). Turning one
  on shows exactly what you approve: where it connects, the keys it keeps and its files at that version.
- **Connect** opens a dialog with APX and the service joined by dots, for its keys or its sign-in.
- **Add** installs from an `.apxext` file, an https address or a folder.

APX reads what each catalog package brings from the package itself: it downloads it once, checks it against the
catalog's sha256 and fingerprint, and keeps only its manifest, its listing and its images in its home. Nothing is
installed or run until you install it. APX ships a copy of the official catalog, so the Marketplace lists it offline.

## Do you need one?

Start with the smallest thing that does the job:

| You want | Make |
|---|---|
| Know-how for one project's agents | A [project skill](/extend/skills/) in `.apc/skills/` |
| One more MCP server for your agents | `apx mcps add` (see [MCP servers](/extend/mcp/)) |
| Skills, servers and routines that travel together, shared or reused | **An extension** |
| Code that watches events or adds context to your turns | An extension with a plugin |

## A real example: daily brief

APX's repository ships `examples/extensions/daily-brief`: one skill and a weekday routine that uses it.

<FileTree>
- daily-brief/
  - apx-extension.json
  - skills/
    - daily-brief/
      - SKILL.md
</FileTree>

```json title="apx-extension.json"
{
  "id": "daily-brief",
  "name": "Daily brief",
  "version": "1.0.0",
  "description": "A short morning brief: open tasks, what is due, what others owe you.",
  "skills": "skills",
  "routines": [
    {
      "name": "Morning brief",
      "schedule": { "kind": "cron", "cron": "30 8 * * 1-5" },
      "prompt": "Use the daily-brief skill to write my morning brief."
    }
  ]
}
```

The skill tells the agent to read your open tasks and commitments, write at most eight lines, and answer `SKIP` when
there's nothing worth saying (a routine that answers `SKIP` tells nobody).

## The manifest

The schema is strict: unknown keys are refused.

| Field | What it holds |
|---|---|
| `id` | Lowercase letters, digits, `_` and `-`, up to 20 characters. |
| `name`, `version` | Required. `description` is optional, up to 500 characters. |
| `skills` | A folder of skill folders, each with its `SKILL.md`. |
| `mcp` | Servers by name (letters, digits and `_`): `command` + `args` + `env`, or `url` + `headers`. A command starting with `./` runs from the extension's folder. |
| `routines` | Templates with a `name`, a `schedule` (`cron`, `every` N minutes with N of 5 or more, or `once`) and a `prompt`. |
| `secrets` | Up to 10, each with a `name`, a `label` and an optional `url` where to get it. You type each value once. |
| `plugin` | Optional code; see below. |

An MCP server in an extension can only use the extension's **own** secrets, as `secret://name`. It can't name your
other variables or the environment, so a bundle can't carry your credentials elsewhere.

```json title="An MCP server with its own secret"
"mcp": {
  "crm": { "command": "node", "args": ["./server.mjs"], "env": { "CRM_TOKEN": "secret://token" } }
},
"secrets": [{ "name": "token", "label": "CRM API token", "url": "https://example.com/settings/tokens" }]
```

### Manifest 2

`"manifest": 2` adds what a bigger extension needs. A manifest without it reads as before.

| Field | What it holds |
|---|---|
| `settings` | Values the owner sets, with a `type` (`string`, `number`, `boolean`, `directory`, `file`), a `label`, optional `description`, `default`, `options` (a choice), `required`. A `sensitive` one goes to the secret store and is referenced as `secret://name`; a plain one is referenced as `setting://name` in its servers' arguments, environment, address or headers. `"generate": "random"` (sensitive strings only) makes APX fill a random key at install. |
| `agents` | Ready-made agents (`id`, `name`, `description`, `prompt`) the owner adds from its page. |
| `pages` | Its own HTML pages (`id`, `title`, `entry`), opened from its settings in a sandboxed frame with no network. A page reads and sets only its own settings through `window.apx` (`settings.get`, `settings.set`, `secrets.has`, `secrets.set`, `close`). |
| `apps` | Widgets or apps (`.apxart` files) the owner adds to Apps from its page. |
| `hosts` | The hosts its code connects to, shown before it is turned on. |
| `platforms` | The systems it runs on (`darwin`, `linux`, `win32`); it does not turn on elsewhere. |
| `companion` | An app on another device: `name`, `platform` (`android`, `android-tv`, `ios`, `macos`, `windows`, `linux`), the app `file` in the package or a store `url`, `steps`, and `pairing`: `{ "with": "apx" }` pairs it with APX as a device (a code and QR), `{ "with": "extension", "server", "tool" }` asks the extension's own tool for the code. |

Nothing an extension brings is added by itself: its agents and apps wait for **Add**, its companion app for
**Pair**. Its settings, pages, agents and apps show on its page in the Marketplace, or with `apx extensions` in the
terminal; `apx extensions set <id> name=value` sets them (`name=-` reads a sensitive value from stdin).

## Install it

An extension comes as a folder, as an **`.apxext` file** (the folder zipped; the packages APX publishes come this way)
or from an **https address** of one. APX shows what it brings before it writes anything, and installs it off.

<Tabs>
<TabItem label="Panel">

<Steps>

1. Double-click an `.apxext` file, or drop it on the APX window. Or open the **Marketplace** and press
   **From a file** or **From a URL** (the **Install** dialog also takes a folder).

2. Look at what it brings: its skills, servers, the secrets it asks for, its plugin, and whether it is **Official**
   or **Third party** (below). Then **Install off**.

3. Fill in its keys (**Edit**), then turn it on.

4. Its routines are suggestions: **Add to Routines** puts one in Routines, turned off until you turn it on.

</Steps>

</TabItem>
<TabItem label="Terminal">

```bash
apx extensions inspect ~/work/daily-brief                          # what it would bring; nothing is installed
apx extensions install ~/work/daily-brief                          # a folder, copied in, off
apx extensions install ~/Downloads/daily-brief.apxext              # a file on this computer
apx extensions install https://example.com/daily-brief.apxext      # a download (https only)
apx extensions secret <id> <name>                                  # a declared secret's value, on stdin (--clear removes it)
apx extensions on daily-brief
apx extensions rollback daily-brief                                # back to the version installed before
apx extensions                                                     # installed ones, on or off
apx extensions off daily-brief
apx extensions rm daily-brief
```

An `.apxext` given to the terminal is read on the terminal's computer and sent to the core, which may run elsewhere;
a folder is read where the core runs.

Installing copies plain files into APX's home and fingerprints them. If the installed copy changes on disk, APX turns
the extension off at its next start until you approve it again. To take changes from the original folder or address,
install it again or use **Read again** / **Download it again** in its detail.

### What an `.apxext` may hold

It is a plain zip of the extension's folder: `apx-extension.json` at the top, or inside one top folder (how zipping a
folder by hand packs it). APX refuses the whole file, before writing anything, when it holds a link, an encrypted
entry, a path that leaves the folder (`..`, an absolute path), sizes that don't match what unpacks, two names one disk
would take as one, more than 2,000 files or more than 50 MB unpacked. The file itself is at most 20 MB. `.git`,
`node_modules`, and what a Mac adds when zipping (`__MACOSX`, `.DS_Store`, `._` files) are left out.

### Official or third party

APX compares the extension's fingerprint (the same one turning it on approves) with APX's official catalog. It is
**Official** when the catalog lists that id and version with exactly those files; anything else, including an official
package with one byte changed, is **Third party**. Nothing is signed: what decides is that the files match the ones APX
publishes. APX asks for the catalog only when you inspect or install an extension, keeps it in its home, and uses that
copy when it can't reach it; with no copy, the dialog says it couldn't tell. A different catalog address can be set
with `APX_MARKETPLACE_INDEX` ([Configuration](/reference/configuration/)).

### Your own catalogs

**Add › Add catalog** (or `apx extensions catalogs add <source>`) adds a list of extensions for yourself: a GitHub
`owner/repo`, a git address, an https address of an index, or a folder. Suggested ones (Anthropic's Knowledge Work and
Claude plugins) are one click away. Everything from them is **Third party**; APX's own catalog always stays.

- APX reads its own index format and Claude Code's `.claude-plugin/marketplace.json`. A Claude plugin installs turned
  into an extension: its skills, its `.mcp.json` servers (a `${VAR}` in them becomes a key you type once), its
  `agents/` as ready-made agents, its license and readme. Commands and hooks have no APX counterpart and are left out.
- A plugin from another repository counts only pinned to a commit (`sha`); it is read at that commit.
- Each plugin's license is read before it is listed (its own, else its repository's). Only licenses that allow a copy
  (MIT, Apache-2.0, BSD, ISC, MPL-2.0, Unlicense, CC0, 0BSD) are converted; the rest are listed as left out, with why.
- APX keeps the commit each catalog was read at; **Read again** takes its newest.

### Updates and going back

Installing another version of one you have keeps the one before beside it. The dialog shows what the new version adds
(a server, a host it connects to, a secret, a routine, what its plugin may reach) and what it drops.

- An extension that is on **stays on** only when the new version is official and asks for nothing more.
- Otherwise it is off until you turn it on, and its card lists what it adds.
- **Back to 1.0.0** (the version kept) swaps it with the version kept before, each as you had approved it (on or off). Pressing it
  again goes forward.

## Plugins

When files aren't enough, an extension can bring a plugin: a `.mjs` file that runs in its own process, watches events
(a task changed, a message arrived…) and can add context to your turns.

```json
"plugin": { "entry": "plugin.mjs", "observe": ["task.updated"], "context": false, "network": false }
```

It runs sandboxed with Node's permission model: it reads only its folder, writes only its data folder, starts no
processes and can't call APX. It reaches the internet only with `"network": true`, and never this machine. What it
adds as context reaches the agent as outside data, not as instructions.

<Aside type="caution">
An extension with a plugin runs code on your computer. The panel says so before you turn it on: do it only if you
trust its author.
</Aside>

<Aside type="tip">
APX ships an `apx-extensions` skill for Claude Code, Codex and other agent apps, so you can ask one of them to build
an extension for you. See [Skills](/extend/skills/#teach-other-agent-apps-to-use-apx).
</Aside>
