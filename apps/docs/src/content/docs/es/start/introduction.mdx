APX es un equipo de agentes de IA que vive en tu máquina. Tenés una secretaria que te conoce, agentes que trabajan
dentro de tus proyectos y un navegador que ellos manejan mientras mirás. Les hablás desde donde estés: la app de
escritorio, la terminal, el teléfono o las apps de chat que ya usás.

Es open source y corre en tu computadora o en un servidor tuyo. Tus proyectos siguen siendo carpetas comunes, tu
estado vive en una sola base de datos local y los modelos son los tuyos: tu suscripción o tus API keys.

<Shot name="home-hero" alt="El Inbox con el chat de Home abierto: una conversación corta con la secretaria" caption="Home, tu secretaria, en la app de escritorio" />

## Probalo

La app de escritorio es la forma más fácil de empezar: bajala desde [Instalar](/es/start/install/) y seguí el
asistente. Desde una terminal, una línea instala el core y el comando `apx`, y después `apx desktop` abre la app:

## Conocé al equipo

- **Home** es tu secretaria. Te responde en la app, en la terminal y en tus canales, tiene a la vista tus
  compromisos, puede abrir y cerrar tu día con un resumen corto y le pasa trabajo al resto del equipo. Su chat es una
  sola conversación en todos lados: lo que mandás por Telegram cae en el mismo lugar que lo que escribís en la app.
- **Los agentes de proyecto** viven en las carpetas de tus proyectos, cada uno en un archivo Markdown chiquito con
  nombre, rol, cara e instrucciones. Lucía puede llevar el proyecto Acme Store mientras Tomás arregla el checkout y
  Vera escribe el newsletter.
- **El navegador** viene adentro de la app de escritorio. Los agentes abren pestañas, leen páginas y completan
  formularios; vos podés tomar el control cuando quieras, y las contraseñas, códigos y tarjetas te los devuelve a vos.

Les hablás a todos desde la **app de escritorio**, la terminal **`apx`**, tu **teléfono** y **Telegram, WhatsApp,
Discord o Slack**. Cada una es una ventana al mismo core, así que nada se desincroniza.

## Una sola forma de hacer cada cosa

APX v2 es una reescritura con una regla: hay una sola forma de hacer cada cosa. Donde v1 tenía muchos caminos para lo
mismo, v2 tiene uno, y todos los clientes pasan por ahí.

| Qué | v1 | v2 |
| --- | --- | --- |
| Caminos de código que corren un turno | unos 23 | **1** |
| Formas de hablarle a un agente | unas 40 | **1** (`threads.send`) |
| Formas de que un agente le hable a otro | 12 | **1** |
| Formas de armar lo que lee el modelo | 9 | **1** |
| Lugares donde vive una conversación | 10 | **1** (hilo, corrida, pasos) |
| Superficie de API | unos 378 endpoints | **un registro tipado** de unos 230 métodos |

### Prompts chicos, en cada llamada

Cada paso de cada turno vuelve a mandar el prompt de sistema y las definiciones de herramientas, así que su tamaño se
paga una y otra vez. APX los mantiene chicos, y un test rompe el build si se pasan del presupuesto.

| App | Primera llamada al modelo en una instalación nueva |
| --- | --- |
| **APX v2** | **≈ 8.200 tokens** |
| Hermes | ≈ 13.000 tokens |
| APX v1 (Telegram, terminal, escritorio) | ≈ 13.200 tokens |
| OpenClaw | ≈ 13.200 tokens |
| APX v1 (chat web, API, rutinas) | ≈ 23.600 tokens |

Las herramientas MCP se encuentran con una herramienta de búsqueda en vez de mandarse una por una. En una instalación
real con diez servidores MCP, una respuesta de una línea pasó de unos 64k tokens a unos 12k, y desde la segunda
llamada cerca del 97% sale de la caché de prompts del proveedor.

<Aside type="tip" title="¿Venís de APX v1?">
v2 corre al lado de v1 y puede importar tus proyectos, agentes, chats y configuración. Arrancá en
[Si venís de v1](/es/start/from-v1/).
</Aside>
