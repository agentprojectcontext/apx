# Site routing

The web home and comparisons share `src/components/web/WebHeader.astro` and `WebFooter.astro`. Header links, repository, Discord, language and theme controls are the same on every web page. Language links retain the comparison being read. On small screens the section navigation is a horizontally scrollable row, not hidden. The footer lists only published comparisons and existing documentation sections.

## Documentation addresses

Starlight content stays in its existing source directories. The supported `docsLoader.generateId` maps English content to `/docs/<section>/<page>/` and Spanish to `/es/docs/<section>/<page>/`. Sidebar generation still refers to source directories, not URL IDs. Starlight keeps its own documentation header, search, navigation, language selector and theme controls.

`src/doc-routes.mjs` is the shared address mapping for Markdown links and web links. It adds `DOCS_BASE` exactly once. The default is `/` on `https://apxagent.app`; `DOCS_BASE=/apx/` also supports a Pages project prefix. Local development and build must use the same values.

All 78 old content addresses have a static HTML page generated by `src/pages/[...legacy].astro`. `/docs/` and `/es/docs/` also lead to their respective introductions. These pages contain a new canonical URL, `noindex,follow`, an immediate meta refresh and a visible fallback link. JavaScript preserves the query and fragment using `location.replace`.

GitHub Pages cannot send a custom HTTP 301 from these HTML files. Redirect responses are HTTP 200; without JavaScript, the meta refresh reaches the new page but query and fragment preservation is not guaranteed. Old heading IDs remain unchanged. Existing routes with a trailing slash or `/index.html` use normal static hosting resolution; unknown routes are not redirected speculatively. The sitemap contains only canonical web and documentation pages, not compatibility pages.

## Historical routing collisions: approved current-documentation precedence

The assembled Pages site also serves v1 documentation under `/v1/`. Its existing 404 script maps missing `/docs/*` to `/v1/*`, strips `/apx/`, and strips `/v2/`. A real v2 HTML file now wins before the 404 script can run. Five historical English v1 addresses would therefore change their meaning:

- `/docs/concepts/agents/`
- `/docs/concepts/memory/`
- `/docs/concepts/projects/`
- `/docs/reference/troubleshooting/`
- `/docs/start/introduction/`

The approved policy is to prioritize current documentation at these five `/docs/` addresses. Their historical content remains at the corresponding `/v1/` addresses. Historical Spanish addresses use `/docs/es/*`, which still falls back to `/v1/es/*`; the new Spanish tree is `/es/docs/*`. `/docs/` was already a current-introduction alias before this change. This routing decision does not authorize publication.

[The full historical inventory](HISTORICAL_ROUTES.md) covers all 80 v1 pages: five English content collisions, the pre-existing root alias and 74 non-colliding historical aliases. All 40 Spanish legacy addresses retain v1 destinations.

The workflow now calls `scripts/assemble-site-cli.mjs`, backed by the same `assembleSite` function used in browser tests, instead of duplicating assembly shell commands. It copies the supplied v1 build without changing it, reserves the version directories, copies the installers and injects the existing 404 redirect behavior. It refuses an already existing output directory. No historical redirect policy changed in this extraction.

The reproducible assembled-site suite requires a real v1 build, not placeholder documentation:

```sh
DOCS_V1_DIST=/path/to/v1/docs/dist pnpm exec playwright test --config e2e/assembled-docs.config.ts
```

Run this from the repository root after building v2; build v1 in a separate temporary copy with `DOCS_BASE=/v1` using its pinned Node/pnpm versions as the workflow does. The tests assemble both builds in disposable directories and serve real static files, using the assembled 404 only for missing paths. They cover desktop/phone, existing v1/v2 pages, `/docs/`, `/apx/` and `/v2/` aliases, queries/fragments, installer byte equality, unknown routes, JavaScript-disabled behavior and comparison navigation. The exhaustive historical test checks all 80 original HTML pages byte for byte under `/v1/`, all `/docs/`, `/apx/docs/` and `/docs/…/index.html` browser destinations, queries/fragments and visible content. It asserts the approved five current-content overrides, the pre-existing root alias and all 74 preserved historical aliases, and attaches the complete expanded inventory. Publication still requires separate approval.

An isolated assembled-site check reproduced these five collisions. `/apx/` and `/v2/` nested-page aliases preserve queries and fragments across the new v2 redirects. The `/v2/` root now preserves both with JavaScript; its no-script meta refresh still reaches `/` but cannot preserve them. Legacy aliases implemented only in the 404 script require JavaScript: without it, missing `/docs/*`, `/apx/*` and nested `/v2/*` paths remain on the 404 page; direct `/v1/` addresses still work. Unknown documentation routes still end on a 404 instead of looping.

The 404 script resolves a proposed destination with the browser URL parser and checks that its origin equals the current origin before redirecting. Network-path and backslash aliases such as `/apx//example.com` and `/v2//example.com` cannot send a visitor to another site. Browser regressions intercept external navigation and assert that malformed aliases stay on the local 404.

The Pages workflow runs this assembled-site browser suite before artifact upload and deployment, using its actual v1 and v2 builds. Changes to the suite also trigger the workflow. Chromium runs both desktop and phone projects, including the exhaustive historical inventory and no-script cases; a test failure blocks publication. The workflow installs the existing locked root Playwright dependency with lifecycle scripts disabled because this suite serves already-built static documentation and requires no application builds. No new dependency or gate exception is introduced.

The shared home/comparison header retains the language selector, theme toggle, circular GitHub icon, Discord icon and theme-aware Download button. Download leads to the current language's home `#download` section, including from comparisons. At narrow widths the action labels collapse to accessible icons; no action is hidden, and the shared navigation remains scrollable.

## Search and installation

Pagefind is rebuilt from the new documentation HTML and returns `/docs/…` or `/es/docs/…` addresses. Compatibility pages are not documentation search results. Search must be tested against a production build; Astro development mode does not generate the search index.

Install scripts remain at `<base>install.sh` and `<base>install.ps1`, outside documentation. No installer contents or release workflow were changed. Root and `/apx/` deployments are checked separately; the remote Pages deployment and custom-domain configuration still need verification at publication time.

## Checks

From `apps/docs`, run `pnpm build && pnpm check`. For a project prefix, run `DOCS_BASE=/apx/ pnpm build && DOCS_BASE=/apx/ pnpm check`. Restore the root build before sharing the root preview. The built-artifact tests verify every old/new documentation pair, canonical URLs, sitemap membership and bilingual page preservation. From the repository root, run `pnpm exec playwright test --config e2e/docs-comparisons.config.ts` for browser navigation, language, theme, search, installer downloads, redirects and comparison reading progress at desktop and phone widths.

The explicit `@astrojs/sitemap` dependency reuses the integration already required by Starlight. It is declared directly to use its supported filtering and locale configuration, excluding compatibility pages without post-processing generated XML or relying on a transitive import.

Docs impact: updated — this file, its Spanish counterpart, README and bilingual comparison guides explain the new routes and compatibility limits. No core, protocol, private state or authorization changes.
